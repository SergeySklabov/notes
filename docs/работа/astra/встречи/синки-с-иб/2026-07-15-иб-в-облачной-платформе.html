Протокол встречи

Тема: Ежемесячный синк по информационной безопасности в контексте Облачной платформы Участники: @Сергей Склабовский, @Николай Корнаев, @Дмитрий Тайлаков, @Максим Куртин, @Сергей Марченков, @Виталий Козловский

Контекст

Ежемесячный синк команды облачной платформы с ДИБ для сверки статусов по аудиту безопасности компонентов ACP: SDN, IAM и процессу взаимодействия по ИБ-рекомендациям. Встреча перенесена с предыдущей даты.

SDN (СДН) - статус аудита

@Николай Корнаев доложил: анализ SDN завершён, вывод отгружен. Остался техдолг - дописать требования по логированию (ТЗ в работе). Проведена демка на ДМКЕ по сценариям SDN + IAM - связка отработана, выявились два момента, один из которых по логированию. По остальному - ОК.

OpenvSwitch - замечание ИБ

Критическое замечание: компонент OpenvSwitch используется не из пакетной базы Brest, а из стороннего источника, что подменяет штатные функции Brest. @Николай Корнаев уточнил: это не блокер, но важный вектор, который надо учитывать при разработке. @Андрей Иволга (RnD) не смог оценить объём доработок - договорились вернуться после его обратной связи.

IAM (ЯМ) - статус аудита

Критичных замечаний со стороны ИБ нет, изменений не требуется.

Процесс заведения задач по ИБ-рекомендациям

Обсудили формат: @Николай Корнаев описал три сложившихся сценария работы с командами: (1) команда сама заводит задачу, (2) команда даёт доступ к пространству и Николай заводит сам, (3) для организационных замечаний (документация, регламенты) - свободный формат. @Дмитрий Тайлаков предложил расширить существующий класс AirBug (AIC Bug), чтобы туда ложились все запросы по ИБ-рекомендациям (доработки, документация и т.д.), не смешивая с Feature Request и обычными багами. @Сергей Склабовский поддержал, отметил что надо не забыть прописать workflow.

ДИБ-запрос на ИБ-проверку перед декомпозицией

@Дмитрий Тайлаков напомнил о договорённости: перед началом декомпозиции требований команда формирует ДИБ-запрос на ИБ-проверку изменений в компоненте в рамках конкретной фичи. Один такой запрос должен быть заведён (по одной из feature request) - @Андрей Крюков или @Максим Югай должны были завести.

Переход с Aldepro на FreeIPA и отказ от СРК в контексте Rubackup

@Сергей Склабовский доложил: команда рассматривает отказ от Aldepro в пользу FreeIPA и опциональность Rubackup (чтобы не тянуть избыточную зависимость и снять административные ограничения для клиентов). @Максим Куртин (ИБ) подтвердил: технических блокеров со стороны ИБ нет, вопрос продуктовый/лицензионный.

SAST-анализ кода на постоянной основе

@Сергей Марченков доложил: ИБ на постоянной основе анализирует репозитории - AIC инсталлера, AIC Go-библиотек, KUP (подключили по запросу команды BRIS). High/Critical требуют реакции от разработки. Команда Aldepro имеет security-чемпионов, которые сами отслеживают и заводят задачи - ИБ даже не успевает. По остальным компонентам ИБ тэжит и ждёт реакции.

Отчёты по уязвимостям инсталлера

@Дмитрий Тайлаков спросил @Сергея Марченкова о реакции разработчиков на отчёты. Процесс остановился после того, как задачи завели - дальше не контролировали. @Сергей Марченков создаст фильтр для отслеживания. Также @Дмитрий Тайлаков скорректировал @Андрея Еровикова: баги по инсталлятору надо заводить в AIC-проект разработческий (AIC SIP), а не в продуктовый AIC.

Статусная страница проектов

@Николай Корнаев анонсировал: готовит страницу Confluence с актуальной статусной таблицей по проектам (SDN, IAM, тенант). В блоке АЦП будут все продукты с исходными данными и перечнем ответственных. Пока не готова - как доделает, разошлёт письмом.

Целевая архитектура IAM

@Сергей Склабовский: внутри команды согласуют целевую архитектуру IAM, затем вынесут на обсуждение с ИБ на следующем синке.

Решения

  • OpenvSwitch - не блокер, но критический вектор на будущее; вернуться после оценки RnD
  • Формат ИБ-задач - расширить класс AirBug (AIC Bug) для доработок по рекомендациям ИБ
  • FreeIPA / Aldepro / Rubackup - технических блокеров со стороны ИБ нет, вопрос продуктовый
  • SAST-анализ - на постоянной основе; High/Critical требуют реакции от разработки
  • ДИБ-запрос - перед декомпозицией требований направлять на ИБ-проверку
  • IAM - критичных замечаний ИБ нет, изменений не требуется

Риски

  • OpenvSwitch - 🟠 используется не из пакетной базы Brest, что создаёт риск совместимости и безопасности. Объём доработок не оценён - может потребовать серьёзных изменений в компоненте
  • SAST High/Critical без реакции - 🟡 уязвимости могут накапливаться, если разработка не реагирует на заведённые задачи. Процесс контроля отсутствует (задачи заводятся, но не отслеживаются)
  • Aldepro -> FreeIPA - 🟡 миграция может затронуть лицензионные/коммерческие соглашения, требуется согласование с продуктовой командой
  • ДИБ-запрос не заведён - 🟡 договорённость о前置-проверке ИБ не реализована, запрос до сих пор не создан

AAR (After-Action Review)

1. Что планировали?

Ежемесячный синк для сверки статусов по аудиту безопасности компонентов ACP (SDN, IAM) и обсуждения процесса взаимодействия по ИБ-рекомендациям.

2. Что получилось?

Удачно:

  • SDN: аудит завершён, демка проведена, остался только техдолг по логам
  • IAM: подтверждено отсутствие критичных замечаний
  • OpenvSwitch: замечание зафиксировано, вектор ясен, не блокер
  • AirBug: договорились о формате, @Дмитрий Тайлаков предложил рабочее решение
  • FreeIPA/Rubackup: ИБ не видит технических блокеров

Неудачно:

  • SAST-уязвимости: процесс контроля отсутствует - задачи заводятся, но не отслеживаются
  • ДИБ-запрос: договорённость есть, но запрос так и не заведён
  • OpenvSwitch: объём доработок не оценён - требуется повторное обсуждение с RnD

3. Почему?

  • Процесс контроля SAST-задач не был формализован - каждый сам заканчивает на этапе заведения задачи
  • ДИБ-запрос не назначен на конкретного ответственного с дедлайном
  • OpenvSwitch требует технической оценки от RnD, которая пока не проведена

4. Что будем делать иначе?

  • Формализовать процесс реакции на SAST - @Сергей Марченков создаст фильтр, @Дмитрий Тайлаков пропишет workflow AirBug
  • Назначить ответственного за ДИБ-запрос - уточнить у @Андрей Крюков / @Максим Югай на ближайшей встрече
  • OpenvSwitch - @Сергей Склабовский инициирует повторный запрос к @Андрей Иволга

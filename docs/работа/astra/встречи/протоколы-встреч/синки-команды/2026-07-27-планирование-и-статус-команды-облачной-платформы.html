Post-meeting: разбор инцидента SDN + IAM + Brest

Проблема: при установке платформы не работала интеграция IAM с Brest для SDN.

Корневая причина: функционал получения токена IAM в Brest был реализован, но требования по настройке IAM (клиент для Brest) и конфигурации Brest не были переданы в инсталлятор. На этапе тестирования нашли, разработчик Дима Конычев поправил локально, но баг не завели (Галина думала, что заведёт Конычев, а Конычев увольнялся). При финальных прогонах полного интеграционного тестирования не было - проверяли только по заведённым баг-репортам.

Решение: добавить обязательный шаг в декомпозицию фичи - проверка необходимости изменений в автоматизации (инсталлятор). ТПМ, ответственный за фичу, либо передаёт требования в инсталлятор, либо явно отписывает «автоматизация не требуется». Задача создаётся автоматически при декомпозиции.

Решения

  • Мини-архком платформы - встречи на троих архитекторов (@Андрей Крюков, @Максим Югай, @Александр Шадрин), лидирует Андрей Крюков
  • Архитектурные серии 4 и 5 - quasi-финальная (среда), финальная (пятница)
  • Бэкап платформы - только Brest (не RuBackup). Александр Лещев готовит требования для инсталлятора
  • Активация по редакциям - одна сборка, лицензия определяет редакцию. Экономия времени сборки, повышение защищённости
  • Декомпозиция - шаг автоматизации - при декомпозиции каждой фичи добавлять задачу «проверить необходимость изменений в автоматизации». ТПМ фичи либо передаёт в инсталлятор, либо явно закрывает
  • 2.3 - запуск - формирование начинается на этой неделе через AICBUG/PBR
  • RnD - формат - регулярный синк раз в две недели
  • Платформенный бэкап - отдельный общий запрос на все компоненты (IAM, SDN, APIM, FreeIPA)
  • Ольга Милащенко - загрузка - отдельная встреча: ТПМ-ы определяют, какие задачи готовы передать Ольге на проработку

Анализ встречи 2026-07-27

5 главных тем

  1. Старт нового спринта - все компоненты. Закрытие предыдущего спринта (13.07-27.07), фиксация целей на 27.07-10.08. Прогресс по ключевым направлениям: Boatsman, DR, SDN, IAM.
  2. Процесс БТ сломан - требования идут мимо архитекторов. Конфликт Андрея Крюкова с текущим процессом привёл к решению создать мини-архком. Первопричина: ТПМ-ы пишут техническую реализацию вместо бизнес-требований.
  3. Инцидент SDN+IAM+Brest - post-mortem вскрыл системную проблему: требования к автоматизации не передаются в инсталлятор. Решение: обязательный шаг «проверка автоматизации» в декомпозиции каждой фичи.
  4. Активация по редакциям - переход от трёх сборок к одной. Лицензия определяет редакцию. Экономия времени и повышение защищённости.
  5. Ольга без загрузки - аналитик без артефактов при сжатых сроках 2.2. Симптом более широкой проблемы: ТПМ-ы не передают проработанные материалы аналитику.

AAR (After-Action Review)

1. Что планировали?

Старт нового спринта: итоги предыдущего (13.07-27.07), планы на 27.07-10.08, разбор cross-cutting вопросов.

2. Что получилось?

Удачно:

  • Прошли по всем 12 участникам, каждый дал статус и цели спринта
  • Закрыт предыдущий спринт - зафиксированы выполненные задачи
  • Принято решение по мини-архкому - реакция на сломанный процесс БТ
  • Post-mortem инцидента SDN+IAM+Brest - выявлена корневая причина, предложен механизм предотвращения (шаг автоматизации в декомпозиции)
  • Активация по редакциям - архитектурное решение принято
  • Бэкап платформы - только Brest, вопрос закрыт

Неудачно:

  • Процесс БТ не работает - большая часть времени ушла на выяснение, почему требования идут мимо архитекторов
  • Ольга без загрузки - симптом системной проблемы
  • Не уложились в тайминг (1ч 30м основная часть + 15 мин post-mortem)

3. Почему?

  • 12 участников - каждый с контекстом, сложно уложиться
  • Процесс БТ вскрылся как болезненная точка - потребовал немедленного обсуждения
  • Post-mortem был необходим, но занял дополнительное время

4. Что будем делать иначе?

  • Мини-архком - регулярные встречи архитекторов для синхронизации (@Андрей Крюков)
  • Шаг автоматизации в декомпозиции - обязательная проверка для каждой фичи (@Дмитрий Тайлаков)
  • Встреча по загрузке Ольги - определить поток задач от ТПМ к аналитике (@Сергей Склабовский)
  • Формат встреч - пересмотреть: разделить платформу и компоненты (@Сергей Склабовский)

AAR (After-Action Review)

1. Что планировали?

Середина спринта - статус каждого участника по компонентам, сверка прогресса по целям спринта.

2. Что получилось?

Удачно:

  • Прошли по всем 12 участникам
  • TROK: получены конкретные цифры производительности - принято решение уходить на 2.3
  • FreeIPA: регрессия подтверждена и Brest, и BillManager - можно переходить
  • SDN метрики: требования переданы, задачи разделены между командами
  • Установлен регулярный синк с RnD (Александр Лещев)
  • Встреча с RnD проведена - 2026-07-20 Встреча с RnD: согласована схема бэкап платформы, IAM в Brest (май 2027), новые редакции ACP
  • Новый регламент AICBUG согласован

Неудачно:

  • Не уложились в тайминг (1ч 30м вместо 1ч)
  • Boatsman ограничение BillManager не решено - только костыль
  • DR тесты затягиваются (1 из 50 ВМ не реплицируется)

3. Почему?

  • 12 участников - сложно уложиться в час
  • Boatsman упёрся в архитектурное ограничение BillManager
  • DR тесты требуют много времени (3 часа на 50 ВМ)

4. Что будем делать иначе?

  • Формат трекинга - Сергей подготовит предложение, чтобы видеть статус по каждому компоненту (требования -> разработка -> тесты)
  • Boatsman - завтра с Boatsman, в среду с Bill - искать обходные пути

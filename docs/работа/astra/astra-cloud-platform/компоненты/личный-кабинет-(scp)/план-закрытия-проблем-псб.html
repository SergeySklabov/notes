Цель: Понять, какие действия нужны от команды Астры по каждой проблеме ПСБ Источники: PSB/ПСБ-БМ-вопросы-и-потребности.md, demo/что-не-хватает-до-zvirt.md, demo/что-есть-но-не-в-mvp.md, demo/полная-карта-платформы.md

Условные обозначения

МеткаЗначение
🟢 MVPВходит в MVP ACP 2.2.0 (ноябрь 2026)
🟡 2.3+Планируется в 2.3 / 2027 H1
🔵 3.0+Дальняя перспектива
🧩 ФронтЗадача на фронт (SCP / React)
⚙️ БэкЗадача на бэкенд (IaaS-оркестратор / API)
🏗️ ПлатформаЗадача на платформенную команду (Брест / SDN / TMS)
🔌 ИнтеграцияЗависит от внешнего вендора / продукта

Категории проблем

Проблемы ПСБ делятся на 4 уровня — по тому, кто и когда должен их решать:

  1. 🟢 Уровень LK (фронт + API) — что можем сделать в рамках SCP
  2. 🟡 Уровень IaaS-оркестратора — требует доработки API
  3. 🔴 Уровень платформы — требует доработки Брест, SDN, TMS
  4. ⚫ Уровень BillManager — требует доработки вендорского продукта

Разбор каждой проблемы

1. Папки/области ресурсов вместо VDC

В рамках каждого клиента несколько областей (папок) ресурсов для разной ролевой модели.

АспектДетали
Пункт в реестреп. 56
Текущий статусЖдём ответа от ДВиС
Уровень⚫ Уровень BillManager
Что нам делатьЖдать ответа ДВиС. Это не наша задача — это изменение модели VDC в BillManager
План БЕсли ДВиС не могут — проработать теги/метки как альтернативу (см. п. 5 ниже)
Когда ждатьНе раньше 2.3+ (2027 H1)

2. Группировка ресурсов в VDC

Ресурсы сплошным списком, нельзя объединить в группы (например по сервису).

АспектДетали
Пункт в реестреп. 57
Текущий статусВ дорожной карте, сроков нет
Уровень⚫ Уровень BillManager + 🧩 Фронт
Что нам делатьНа фронте: продумать UI группировки (теги, папки, группы) — в mockup можно показать концепт. На бэке: требуется API группировки от БМ или IaaS
ЗависимостиДВиС / группа IaaS
План для демоПоказать макет группировки по тегам — это будет выглядеть как решение, даже если бэк не готов
Когда🟡 2.3+

3. Ролевая модель: Админ / Админ ИБ

Организовать роли: администратор клиента и администратор ИБ (только просмотр).

АспектДетали
Пункт в реестреп. 58
Текущий статусНа 3-й линии
Уровень🏗️ Платформа (TMS + IAM)
Что нам делатьВ рамках MVP — ничего. Ролевая модель убрана из ВИ (PULSE W28). Нужна архитектура пер-сервисного RBAC, которая зависит от TMS
ЗависимостиTMS (не существует, 2027 H1), IAM (расширенный RBAC, 2027+)
План для демоЧестно сказать: «В ноябре — единая роль пользователя. Разделение админ/просмотр — в 2027»
Когда🔵 2027 H2+

4. Логирование действий админов

Кто, когда и какие действия на ВМ осуществлял (включение, перезагрузка). Логи доступны Администратору ИБ.

АспектДетали
Пункт в реестреп. 59
Текущий статусНа 3-й линии
Уровень⚙️ IaaS-оркестратор + 🧩 Фронт
Что нам делать1. Уточнить у IaaS: логируются ли действия в оркестраторе? Если да — можно отдавать через API. 2. Фронт: виджет «Последние события» на дашборде и странице ВМ
План для демоПоказать макет «Логи действий» (даже заглушку) — это покажет понимание потребности
Лёгкий шагВ MVP уже есть аудит на стороне IaaS (из что-есть-но-не-в-mvp.md п.5). Спросить у IaaS, можно ли сделать read-only endpoint для SCP
Когда🟡 2.3+ (API от IaaS) / 🟢 MVP-readonly (если endpoint есть сейчас)

5. Фильтрация/поиск ВМ по имени/адресу

Список ВМ не позволяет фильтровать/искать ВМ по имени/адресу.

АспектДетали
Пункт в реестреНет прямого маппинга (близко к п. 60)
Текущий статусДВиС дал рекомендацию, ждём ответа
Уровень🧩 Фронт (SCP)
Что нам делатьЧисто фронтовая задача. Делаем фильтр/поиск в таблице ВМ по: имени, IP-адресу, статусу, ОС. Это стандартный UI-компонент (Input + Select)
Оценка1 спринт (2 недели)
ЗависимостиНет — все данные уже есть в API
План для демоПоказать в mockup фильтры — это быстро и дешево
Когда🟢 MVP (легко дотянуть)

6. Отображение сетей, MAC, интерфейсов ВМ

Список ВМ не отображает сети (в т.ч. импортированных из БРЕСТ), число интерфейсов, IP и MAC-адреса.

АспектДетали
Пункт в реестреп. 61
Текущий статусНа 3-й линии
Уровень🧩 Фронт + ⚙️ IaaS API
Что нам делатьФронт: добавить колонки (сети, IP, MAC) в таблицу ВМ + детальную страницу с vNIC. Бэк: нужно, чтобы IaaS-оркестратор отдавал список vNIC для каждой ВМ
ЗависимостиAPI IaaS-оркестратора (должен быть в MVP)
ОценкаФронт: 1 спринт. Бэк: уточнить у Шадрина
Когда🟢 MVP (если API готов) / 🟡 2.3+

7. Поле «Описание» для каждой ВМ

Добавить поле «Описание» как в VMware (служебная информация, отметки о бэкапе и т.д.).

АспектДетали
Пункт в реестреп. 62
Текущий статусНа 3-й линии, уточняем сроки
Уровень⚙️ IaaS-оркестратор + 🧩 Фронт
Что нам делатьБэк: добавить поле description (или annotations) в модель ВМ IaaS-оркестратора. Фронт: поле ввода на странице ВМ, отображение в списке
ЗависимостиМодель данных IaaS-оркестратора
ОценкаФронт: 0.5 спринта. Бэк: уточнить у Шадрина (должен быть PUT /vm/{id} с полем description)
План для демоПоказать в mockup поле описания — это одна строка на фронте
Когда🟡 2.3+ (если нет в модели IaaS) / 🟢 MVP (если endpoint PATCH есть)

8. Заказ/изменение/удаление датацентров

Администраторы должны иметь возможность заказывать, изменять и удалять датацентры (сейчас — только зона видимости).

АспектДетали
Пункт в реестреп. 63
Текущий статусНа 3-й линии
Уровень🏗️ Платформа (TMS / Брест / IaaS)
Что нам делатьНичего в рамках MVP. Датацентр — инфраструктурная сущность (кластер Брест). Управление ЦОД — функция админ-портала (2027 H1)
ЗависимостиTMS, админ-портал, IaaS-оркестратор (модель ЦОД)
План для демоОбъяснить: «Датацентры — это физическая инфраструктура. В 2026 — админ создаёт, в 2027 — вы сможете сами»
Когда🔵 2027 H1+

9. Смена пароля через БМ

Пользователь должен менять пароль через интерфейс БИЛЛ (иначе — доступ к инфраструктурному домену).

АспектДетали
Пункт в реестреп. 1 / п. 64 / п. 120
Текущий статусПередано в разработку, без сроков
Уровень🧩 Фронт (SCP) + 🔌 IAM
Что нам делатьВ SCP: не делаем смену пароля — это ушло в IAM-портал (решение 26.06). В IAM: редирект на IAM-портал для смены пароля
ЗависимостиIAM портал (должен быть к ноябрю)
План для демоПоказать кнопку «Сменить пароль» → редирект на IAM
Когда🟢 MVP (редирект на IAM) / 🟡 2.3+ (если нужна своя форма)

10. Истекший пароль — не пускать

Система не должна впускать пользователя с истекшим паролем.

АспектДетали
Пункт в реестреп. 1
Текущий статусПередано в разработку, без сроков
Уровень🔌 IAM + LDAP
Что нам делатьНе наша задача. Это функция IAM/FreeIPA: проверка expired password при аутентификации. В IAM уже ведётся работа (CF-4460)
ЗависимостиIAM (команда Максима Югая, RooX)
План для демоОбъяснить: «SSO проверяет пароль при входе. Истекший пароль — блокировка на уровне IAM»
Когда🟢 MVP (IAM должна обеспечить)

11. VNC-прокси через БМ

БИЛЛ должен проксировать VNC-консоль (иначе нужен прямой доступ к фронту БРЕСТ).

АспектДетали
Пункт в реестреп. 6
Текущий статусНужны комментарии специалистов
Уровень🧩 Фронт (SCP) + ⚙️ IaaS + 🏗️ Брест
Что нам делатьВ MVP — не делаем через БМ. Делаем через IaaS-оркестратор: SCP получает .vv файл (VNC-консоль) от оркестратора, пользователь открывает virt-viewer
ЗависимостиIaaS-оркестратор (endpoint получения консоли)
План для демоПоказать кнопку «Консоль» → скачивание .vv файла → открытие в virt-viewer
Когда🟢 MVP (через virt-viewer) / 🔵 3.0+ (браузерная VNC через прокси)

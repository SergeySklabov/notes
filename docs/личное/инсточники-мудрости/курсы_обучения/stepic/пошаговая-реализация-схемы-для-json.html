Шаг 1: объявление схемы

Каждая JSON схема начинается с объявления версии документа $schema, которое указывает на драфт (версию) JSON Schema, используемую для описания схемы. Это необходимо для того, чтобы инструменты валидации(в коде разработки) понимали, какие правила и возможности применять при обработке схемы.

Шаг 2: основной тип документа

JSON Schema позволяет описывать структуру данных, которая может быть разных типов:

  • object — для JSON объектов,
  • array — для массивов,
  • string — для строковых значений,
  • number — для чисел (включает в себя и целые, и числа с плавающей точкой),
  • integer — для целых чисел,
  • boolean — для логических значений true/false,
  • null — для значения null. Тип определяет, какие данные ожидаются в JSON документе. В нашем случае JSON представляет собой объект(объясняется тем, что наш JSON начинается с фигурных скобок {}, что характерно для объектов в JSON), так что основным типом будет object:

Шаг 3: определение свойств

После указания, что наш документ является объектом, мы можем определить свойства этого объекта. Для каждого свойства можно указать его тип, ограничения (например, минимальную длину для строк или минимальное значение для чисел) и другие правила (например, формат для строки).

Начнем с базовых свойств: name (строка), age (целое число), и email (строка, соответствующая формату электронной почты). 

Здесь мы определили три свойства объекта, указав их типы и для age минимальное значение, чтобы возраст не был отрицательным, а для email указали формат (форматы для типа данных string тут: https://json-schema.org/understanding-json-schema/reference/string):

Шаг 4: обязательные свойства

В JSON Schema можно указать, какие свойства являются обязательными для объекта, используя ключевое слово required. Это массив, содержащий имена всех свойств, которые должны присутствовать в объекте.

Для нашего примера сделаем name, age, и email обязательными. Это означает, что любой валидный JSON документ должен содержать как минимум эти три свойства с соответствующими типами данных.

Шаг 5: вложенные объекты и массивы

В JSON Schema можно описывать не только простые типы данных, но и вложенные структуры, такие как объекты и массивы. Это позволяет создавать сложные иерархические модели данных.

  • Объекты описываются аналогично корневому объекту, с определением своих свойств внутри.
  • Массивы описываются через ключ items, который определяет тип данных элементов массива. Это может быть как простой тип данных, так и объект с дополнительными свойствами.

Добавим описание для address (вложенный объект) и phoneNumbers (массив объектов). В address мы определяем два свойства: city и postalCode, оба обязательные. Для phoneNumbers указываем, что это массив объектов, каждый из которых должен иметь свойства type и number.

Шаг 6: массивы сложных объектов

Массивы в JSON Schema могут содержать не только простые типы данных, но и сложные объекты с своим набором свойств. Это позволяет моделировать сложные структуры данных, такие как списки образования или опыта работы, где каждый элемент списка имеет несколько характеристик.

Рассмотрим добавление массивов education и workExperience, которые содержат объекты с детальной информацией. Для education и workExperience мы определяем, что это массивы объектов с конкретными свойствами. Каждый элемент в этих массивах требует наличия всех указанных свойств с соответствующими типами данных и ограничениями.

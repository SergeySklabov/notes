# 🔧 DevOps/SRE — Телеграм-пост (кейс)

---

**Когда PaaS уже жмёт, а IDP — ещё рано. Знакомо?**

Разбирали тут реальный путь SaaS-сервиса (автоматизация документооборота) от прототипа до enterprise-клиентов. Получилась занятная картина с точки зрения инфры.

**Этап 1 — Replit / Lovable**
MVP за 3 дня, $20–50/мес, 5–10 клиентов. Инфра полностью абстрагирована. Всё ок, пока не начинается throttling на shared-контейнерах и таймауты при 5 документах в минуту. Development-first среда, не production-first.

**Этап 2 — Vercel / Heroku**
Git push → автодеплой через buildpacks. Появляются preview-окружения, автоскейлинг, TLS из коробки. Команда 5–15 человек, без DevOps.

Но:
- Нет контроля над сетевой топологией
- Нет кастомного IAM
- Observability ограничена метриками платформы
- VPC? Только enterprise-тариф, и то условно
- Счета непредсказуемы: +40% трафика = +70–90% к счёту (dyno/serverless runtime биллинг)

А потом приходит корпоративный клиент и спрашивает: «Где ваш VPC? Покажите журнал доступа. Какой SLA?»

**Этап 3 — собственная инфра / IDP**
VPC, WAF с кастомными правилами, сегментация по клиентам, SIEM, аудит. Но: 6–12 месяцев внедрения, 1–2 infra-инженера ($6–10K/мес), platform team.

**Где GAP?**
Между этапом 2 и 3 — зона боли. PaaS уже не даёт нужного контроля. IDP — дорого и избыточно. Terraform руками? Можно. Но:
- Поддерживать 3 года
- Онбордить людей
- Стандартизировать окружения
- Не превратить infra-repo в хаос модулей

Terraform — это инструмент. Платформа — это процесс + стандарты + автоматизация + DX.

Компании с 10–50 разработчиками, MRR $20K–$200K — кто из вас сейчас в этом зазоре? Как решаете?

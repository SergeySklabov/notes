## Что входит в MVP ACP 2.2.0 (ноябрь 2026)

| Компонент | Состав | Статус |
|---|---|---|
| **Портал самообслуживания (SCP)** | ~15 UC из ~50. ВМ (CRUD), диски, публичные образы, дашборд (стат-карточки), SSH-ключи | ✅ MVP |
| **IaaS-оркестратор** | ~10+ UC. REST API для ВМ, дисков, образов | 🟡 Зависимость (предоставляет API) |
| **Брест/Crystal** | CRUD ВМ, диски, образы (базовые) | 🟡 Зависимость (предоставляет API) |
| **IAM** | SSO (OAuth 2.0/OIDC), отображение роли из JWT | 🟡 Зависимость (предоставляет API) |
| **SDN** | Только дефолтная сеть тенанта (Brest read-only) | 🟡 Частично |
| **Мониторинг** | Только стат-карточки на дашборде | 🟡 Минимально |

### Чего НЕТ в MVP

| Компонент                                      | Когда    |
| ---------------------------------------------- | -------- |
| SDN полный (VPC, Floating IP, Security Groups) | 3.0+     |
| Ролевая модель (Админ/Админ ИБ)                | 2027 H2+ |
| Мультитенантность (TMS)                        | 2027 H1  |
| Админ-портал                                   | 2027 H1  |
| Квоты и биллинг                                | 2.3+     |
| Снапшоты и backup                              | 3.0+     |
| Свои образы (custom images)                    | 3.0+     |
| CLI / Terraform / SDK                          | 3.0+     |
| Браузерная VNC-консоль                         | 3.0+     |
| Мониторинг (графики, алерты)                   | 2.3+     |

## 11 потребностей ПСБ vs MVP

### Потребность 1 — Папки/области вместо VDC
**Модель VDC → области/папки с разной ролевой моделью**

| Аспект                    | Ответ                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------ |
| **В MVP?**                | ❌ Нет                                                                                                  |
| **Почему**                | Изменение модели VDC — это доработка BillManager (ISPsystem) или появление TMS                         |
| **Что реально в MVP**     | Единый VDC на тенант. Никаких папок/областей                                                           |
| **Когда ждать**           | 🟡 2.3+ (BillManager) или 2027 H1+ (TMS)                                                               |
| **Что сказать заказчику** | «В ноябре — один VDC на тенант. Разделение на области — после доработки BillManager или появления TMS» |

### Потребность 2 — Группировка ресурсов в VDC
**Ресурсы сплошным списком, нельзя объединить в группы**

| Аспект                    | Ответ                                                                                                                                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **В MVP?**                | ❌ Нет                                                                                                                                                                                                             |
| **Почему**                | Нет модели тегов/групп в IaaS-оркестраторе                                                                                                                                                                        |
| **Что реально в MVP**     | Плоский список ВМ с сортировкой и поиском                                                                                                                                                                         |
| **Когда ждать**           | 🟡 2.3+ (если IaaS-оркестратор добавит теги) также зависит от TMS<br>Нужно уточнить а что именно ПСБ хочет видеть - **общий список ресурсов в проекте, сколько фактически потребляется, сколько денег потрачено** |
| **Что сказать заказчику** | «В ноябре — плоский список с поиском. Группировка — после появления тегов в платформе»                                                                                                                            |

### Потребность 3 — Роли Админ / Админ ИБ
**Администратор клиента (управление) и Администратор ИБ (только просмотр)**

| Аспект                    | Ответ                                                                          |
| ------------------------- | ------------------------------------------------------------------------------ |
| **В MVP?**                | ❌ Нет                                                                          |
| **Почему**                | Ролевая модель убрана из ВИ (PULSE W28). Per-service RBAC зависит от TMS       |
| **Что реально в MVP**     | Единая роль: пользователь с полным доступом к своему тенанту                   |
| **Когда ждать**           | 🔵 2027 H2+                                                                    |
| **Что сказать заказчику** | «В ноябре — одна роль пользователя. Разделение Админ/Админ ИБ — не ранее 2027» |

### Потребность 4 — Логирование действий админов
**Кто, когда, какие действия на ВМ. Логи доступны Администратору ИБ**

| Аспект                    | Ответ                                                                                                                                                      |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **В MVP?**                | ❌ Нет                                                                                                                                                      |
| **Почему**                | Аудит есть на стороне IaaS, но UI логов в ЛК — post-MVP. Нет endpoint для SCP                                                                              |
| **Что реально в MVP**     | IaaS логирует действия. Но отображения логов в ЛК — НЕТ                                                                                                    |
| **Когда ждать**           | 🟡 2.3+ (если IaaS-оркестратор сделает read-only endpoint)<br> **уточнить у компонентов по логированию. Должен быть sys.log для выгрузки во внешний SIEM** |
| **Что сказать заказчику** | «Логирование на стороне платформы есть. Интерфейс логов в ЛК — в следующем релизе»                                                                         |

### Потребность 5 — Фильтрация/поиск ВМ по имени и адресу
**Список ВМ не позволяет искать ВМ по имени/адресу**

| Аспект | Ответ |
|---|---|
| **В MVP?** | 🟡 Зависит от API |
| **Почему** | Если IaaS-оркестратор поддерживает фильтрацию (search/query params) — делаем. Если нет — только клиентский поиск по загруженному списку |
| **Что реально в MVP** | Клиентская фильтрация по имени (в браузере). Серверная фильтрация — если API позволяет |
| **Когда ждать** | 🟢 MVP (клиентская) / 🟡 2.3+ (серверная) |
| **Что сказать заказчику** | «Поиск по имени в списке — будет. Поиск по IP — после доработки API оркестратора» |

### Потребность 6 — Отображение сетей, MAC, интерфейсов ВМ
**В списке ВМ видеть сети, число интерфейсов, IP и MAC-адреса**

| Аспект                    | Ответ                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------ |
| **В MVP?**                | 🟡 Зависит от API                                                                    |
| **Почему**                | Нужен endpoint `GET /vm/{id}/nics` от IaaS-оркестратора                              |
| **Что реально в MVP**     | Если API есть — покажем. Если нет — только IP из основной модели ВМ                  |
| **Когда ждать**           | 🟢 MVP (если API готов) / 🟡 2.3+                                                    |
| **Что сказать заказчику** | «Уточняем у команды оркестратора — будут ли детальные данные по сетевым интерфейсам» |

### Потребность 7 — Поле «Описание» для ВМ
**Добавить поле описания для служебной информации**

| Аспект | Ответ |
|---|---|
| **В MVP?** | 🟡 Зависит от API |
| **Почему** | Нужно поле description в модели ВМ IaaS-оркестратора + PATCH endpoint |
| **Что реально в MVP** | Если модель данных позволяет — сделаем. Если нет — post-MVP |
| **Когда ждать** | 🟢 MVP (если API готов) / 🟡 2.3+ |
| **Что сказать заказчику** | «Поле описания — технически простая задача. Решается после расширения модели данных» |

### Потребность 8 — Управление датацентрами
**Администраторы заказывают/изменяют/удаляют датацентры**

| Аспект                    | Ответ                                                                                                      |
| ------------------------- | ---------------------------------------------------------------------------------------------------------- |
| **В MVP?**                | ❌ Нет                                                                                                      |
| **Почему**                | Функция админ-портала, которого нет даже в проекте                                                         |
| **Что реально в MVP**     | ЦОД отображается в информации о ВМ (read-only)                                                             |
| **Когда ждать**           | 🔵 2027 H1+<br> **управление тенантами**                                                                   |
| **Что сказать заказчику** | «Управление ЦОД — функция оператора платформы. В 2026 — через администратора, в 2027 — через админ-портал» |

### Потребность 9 — Смена пароля
**Пользователь меняет пароль через интерфейс БИЛЛ**

| Аспект                    | Ответ                                                                       |
| ------------------------- | --------------------------------------------------------------------------- |
| **В MVP?**                | 🟡 Через IAM                                                                |
| **Почему**                | Решение 26.06: смена пароля — в IAM-портале, не в ЛК                        |
| **Что реально в MVP**     | Кнопка «Сменить пароль» → редирект на IAM-портал                            |
| **Когда ждать**           | 🟢 MVP (редирект на IAM)                                                    |
| **Что сказать заказчику** | «Смена пароля — через корпоративный портал IAM. В ЛК будет кнопка перехода» |

### Потребность 10 — Истекший пароль — не пускать

| Аспект | Ответ |
|---|---|
| **В MVP?** | ❌ Не в ЛК |
| **Почему** | Функция IAM — проверка при аутентификации |
| **Что реально в MVP** | IAM должна обеспечить блокировку при истекшем пароле |
| **Когда ждать** | 🟢 MVP (задача на IAM, CF-4460) |
| **Что сказать заказчику** | «Это проверка на уровне IAM при входе — не функция портала» |

### Потребность 11 — VNC-прокси через БМ
**БИЛЛ должен проксировать VNC-консоль**

| Аспект                    | Ответ                                                                                                 |
| ------------------------- | ----------------------------------------------------------------------------------------------------- |
| **В MVP?**                | 🟡 Через .vv файл                                                                                     |
| **Почему**                | VNC через .vv файл (virt-viewer) — делает IaaS-оркестратор. Браузерная VNC — 3.0+                     |
| **Что реально в MVP**     | Кнопка «Подключиться» → скачивание .vv файла → открытие в virt-viewer                                 |
| **Когда ждать**           | 🟢 MVP (через virt-viewer) / 🔵 3.0+ (в браузере)<br> **добавить что-то про Spice. Проработка SPICE** |
| **Что сказать заказчику** | «Консоль — через нативное приложение virt-viewer. Браузерная консоль — в 2027+»                       |

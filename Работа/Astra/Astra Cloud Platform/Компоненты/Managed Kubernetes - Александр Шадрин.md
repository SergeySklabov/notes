## 1\. Введение

Kubernetes - это платформа для оркестрации, или управления контейнерами. Kubernetes автоматически решает задачи жизненного цикла контейнеров: создаёт их, запускает, масштабирует, распределяет нагрузки и контролирует работоспособность. Контейнер представляет собой изолированную среду, в которой исполняется приложение.

Внедрить Kubernetes можно двумя основными путями:

1. Самостоятельное развёртывание (**Self-managed**) - команда самостоятельно проектирует и настраивает серверную инфраструктуру, после чего устанавливает и администрирует Kubernetes. Это требует глубокой экспертизы, значительных трудозатрат и ресурсов на дальнейшую поддержку.
2. Воспользоваться услугой **Managed Kubernetes** - клиент заказывает кластер через портал самообслуживания, а провайдер предоставляет готовый, полностью настроенный ресурс и берёт на себя его обновления, мониторинг, резервное копирование и техническую поддержку. Это позволяет командам быстро приступить к развёртыванию приложений, не тратя время на инфраструктурные задачи.

## 2\. Цель

Цель настоящего документа - сформировать единое понимание услуги Managed Kubernetes, зафиксировать границы ответственности и описать базовый функционал сервиса.

Документ раскрывает следующие аспекты:

1. Что представляет собой Managed Kubernetes и какую ценность он даёт бизнесу и командам разработки.
2. Какие инфраструктурные задачи берёт на себя платформа в рамках услуги.
3. Какие возможности получает клиент при использовании услуги.
4. Перечень ключевых функций, которые лягут в основу дорожной карты и станут критериями приоритизации развития продукта.

## 3\. Ценность услуги для бизнеса и разработки

## 3.1. Для бизнеса

|  |  |
| --- | --- |
| Зависимость от узких экспертов по Kubernetes | Платформа автоматизирует сложные операционные сценарии - снижается порог входа и потребность в глубокой экспертизе внутри команды. |
| Риски простоя и потери данных | Встроенные механизмы резервного копирования, восстановления и отказоустойчивости повышают доступность сервиса. |
| Сложности с соответствием регуляторным требованиям | Платформа сертифицирована в соответствии со ФСТЭК. |
| Высокие операционные расходы на поддержку инфраструктуры | Операционные расходы снижаются за счёт того, что провайдер берёт на себя рутинные задачи: обновление, мониторинг, восстановление. Команда фокусируется на продукте. |

## 3.2. Для команд разработки

|  |  |
| --- | --- |
| Нестабильная или неконсистентная среда ("у меня работает, а на проде - нет") | Контейнеризация и управляемая платформа обеспечивают идентичные условия на всех стадиях жизненного цикла. |
| Необходимость ручного восстановления инфраструктуры при сбоях | Платформа автоматически обнаруживает и заменяет неисправные узлы. |
| Сложность и риски при проведении обновлений и масштабирования | Изменение конфигурации кластера выполняется через портал самообслуживания в контролируемом режиме: платформа применяет изменения без остановки сервисов. |
| Необходимость тратить время на рутинную настройку инфраструктуры | Заказ кластера через портал самообслуживания: готовая среда за минуты, без ручной настройки и ожидания экспертов. |

## 4\. Инфраструктурные задачи платформы

|  |  |
| --- | --- |
| Управляемый Control Plane | Платформа берёт на себя полное сопровождение компонентов управления кластером: клиент не администрирует их напрямую, а задаёт параметры через настройки сервиса (версия, схема размещения, окно обслуживания). |
| Автоматические обновления | Обновления версий Kubernetes и патчи безопасности применяются провайдером автоматически или по запросу клиента. |
| Встроенная отказоустойчивость | Отказоустойчивость управляющих компонентов обеспечивается при выборе опции "высокодоступный мастер" с размещением в нескольких зонах доступности. |
| Автоматическое резервное копирование | Регулярные резервные копии конфигураций управляющих компонентов кластера. |
| Самовосстановление инфраструктуры | Платформа отслеживает состояние узлов и управляющих компонентов.   При обнаружении сбоев обеспечивает перераспределение нагрузки и восстановление работоспособности кластера без участия пользователя. |
| Наблюдаемость состояния кластера | Платформа собирает и отображает базовые метрики здоровья инфраструктуры: статус узлов, потребление CPU и памяти, события системных компонентов. Клиент видит, что кластер работает стабильно, без необходимости настраивать мониторинг самостоятельно. |
| Учёт потребления ресурсов | Платформа автоматически собирает и агрегирует данные о потреблении вычислительных ресурсов (CPU, память, диск, сеть) по кластерам и группам узлов.   Клиент получает детализированную статистику для контроля расходов. |

## 5\. Возможности для клиента

|  |  |
| --- | --- |
| Управление ресурсами через портал самообслуживания и API | Заказ, настройка и администрирование кластеров через пользовательский интерфейс, API или Terraform-провайдер для автоматизации инфраструктуры без обращения в службу поддержки. |
| Гибкая конфигурация кластера | Выбор версии Kubernetes, уровня отказоустойчивости управляющих компонентов (одна или несколько зон доступности), характеристик узлов (CPU, память) и сетевых настроек под задачи проекта. |
| Контролируемое масштабирование | Горизонтальное масштабирование: автоматическое или ручное добавление/удаление узлов (через портал самообслуживания) в зависимости от нагрузки.  Вертикальное масштабирование: изменение конфигурации ресурсов существующих узлов (CPU, память) через портал самообслуживания с безопасной миграцией рабочих нагрузок.  Платформа обеспечивает перераспределение подов без простоя сервисов. |
| Наблюдаемость за состоянием кластера | Доступ к панели с метриками потребления ресурсов, статусом узлов, системными событиями и логами для оперативного контроля работоспособности. |
| Интеграция с внешними системами | Подключение к кластеру из внешних систем доставки приложений (CI/CD) через стандартные интерфейсы Kubernetes (API, kubeconfig).  Платформа обеспечивает безопасное управление доступом для автоматизации деплоя. |

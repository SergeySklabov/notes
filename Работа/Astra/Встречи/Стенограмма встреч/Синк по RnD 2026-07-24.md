### 02:54-13:42 IAM в Brest — исследование

Александр начал сегодня. Собирает стенд, общается с ребятами по авторизации в FreeIPA и Libvirt. Сложная схема:
- IAM генерирует токен
- Авторизация Brest переоприврается в IAM, который возвращает в Brest
- Libvirt запускает ВМ со своей авторизацией
- В Brest будет встроенный центр сертификации (CA) для генерации сертификатов пользователей
- Сертификаты содержат метки безопасности (целостности, секретности) — Рома добавил в Libvirt 1.8.7
- Людмила: значит в платформу должна идти ОС 1.8.7

Александр: это не финальная версия. Есть центр сертификации (Агафонов), который можно переиспользовать. Схема:
- IPA будет центром сертификации
- Запрашиваем клиентские/серверные сертификаты через IPA
- Пользователи Brest и пользователи ОС связываются через сертификат
- Libvirt спрашивает IPA: можно ли этому пользователю запускать ВМ с такими параметрами?

Существующая схема через Kerberos + Apache — другая, не подходит для Brest. Нужна принципиально новая система авторизации.

Сергей: решаем минимальными усилиями — добавляем центр сертификации через IPA. Если не получится — возвращаемся к удалению Apache, но это пересертификация.

Александр: технических проблем быть не должно. Вопрос с безопасниками — нужно убедиться, что они подтвердят новую схему для сертификации второго уровня. Сейчас рано идти в Nimbus — нужен полный прототип. Возможно, придётся договариваться с центром сертификации и Libvirt.

Людмила: может, описать концепцию? Александр: лучше прототип, потому что цепочка длинная, в любом месте может пойти не так. Месяц на прототип, но Рома в отпуске на 2 недели.

### 20:44-25:48 Контейнеризация платформы

Александр: приоритетная задача — прототип. Концепция гипервизора первого типа (1+):

- Закрытый shell для клиентов (набор команд)

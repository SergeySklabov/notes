## Решения

### Тенанты и TMS
- **Step 0 (минимальная реализация тенантов):** BillManager после создания VDC отправляет запрос в TMS, получает tenant ID и дальше работает с ним. Доработка на стороне BillManager минимальна - нужно только передавать/принимать tenant ID. Этот шаг нужен в любом случае, независимо от выбора целевой архитектуры.
- **TMS (Tenant Management System):** новая подсистема платформы, центральное звено учёта тенантов (создание, жизненный цикл). Разработка - ориентировочно сентябрь-октябрь 2026. Product Manager - @Максим Югай.
- **Тенант = VDC (на Step 0):** единица изоляции ресурсов. В перспективе - иерархия (организация -> тенанты -> проекты), интеграция с IAM, раздельный chargeback.
- **Архитектура (целевая):** API Gateway -> Orchestrators (IaaS, PaaS) -> Brest/SDN/Boatsman. Бизнес-логика оркестрации со временем перетягивается из BillManager в платформенные компоненты.

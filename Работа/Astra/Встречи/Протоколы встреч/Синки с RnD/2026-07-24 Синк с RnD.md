### IAM в Brest — исследование

@Александр Лещев начал исследование сегодня. Собирает стенд, общается с командой FreeIPA и Libvirt. Ключевое архитектурное решение — использовать IPA как центр сертификации платформы вместо текущей Kerberos+Apache схемы:

- Пользователь авторизуется в Brest -> IAM выдаёт токен -> Brest запрашивает клиентский сертификат у IPA -> Libvirt проверяет сертификат и запускает ВМ с метками безопасности
- Сертификаты содержат метки целостности/секретности — Рома добавил в Libvirt 1.8.7 (не финальная версия)
- IPA уже содержит центр сертификации (команда Агафонова), можно переиспользовать
- Пользователи Brest и ОС связываются через сертификат — это обеспечивает сквозную авторизацию

**Статус:** исследование запущено. ~1 месяц на прототип (Рома в отпуске 2 недели, нужен для Libvirt). После прототипа — согласование с безопасниками через Nimbus.

**Риск:** если схема с IPA не сработает — возврат к удалению Apache с полной пересертификацией Brest. Но технических проблем не ожидается.

### Мониторинг Brest

Сергей предложил гипотезу: заменить Astra Monitoring на встроенный мониторинг OpenNebula 6.11.

@Александр Лещев пояснил: мониторинг OpenNebula — только внутренний (для размещения ВМ самой системой). Клиентам этого недостаточно. Astra Monitoring отслеживает состояние серверов, компонентов и пользовательских данных в ВМ. В 6.10-6.11 добавился статус guest agent внутри ВМ, но это не закрывает потребности платформенного мониторинга.

**Решение:** Astra Monitoring остаётся, отказ от мониторинга только средствами OpenNebula.

### Контейнеризация платформы

Приоритетная задача — прототип гипервизора первого типа:
- Brest и все компоненты платформы в контейнерах (Kubernetes)
- Неизменяемая базовая ОС (read-only, эталонный образ)
- Оркестратор контейнеров на CCM
- Закрытый shell для клиентов
- Замена сервера за считанные минуты (динамичная система)

**Блокер:** Brest — цельный продукт, не разбивается на контейнеры. Создана задача в команду Brest на декомпозицию. Нужна помощь разработчиков Brest.

**По компонентам:**
- TROK (SDS) — использует модуль ядра, нужна проработка (агент или контейнеризация)
- IAM — в контейнере
- SDN — вероятно, в контейнере (уточнить у Андрея/Максима)

Сергей: TROK надо плотнее брать — интегрировать с IAM, добавить мультитенантный контекст, сделать платформенным продуктом.

Целевой срок прототипа: вторая половина осени.

### Обновление платформы

Два подхода к обновлению между версиями:
1. In-place обновление компонентов с мержем конфигурации
2. Свежая установка + восстановление конфигурации из бэкапа

Принят второй подход — чистая установка и восстановление данных. Контейнеризация упрощает: новый образ контейнера заменяет старый, данные в отдельном хранилище, миграция скриптами.

@Людмила Руденко: при появлении новых компонентов (IAM, SDN) в новых версиях — инсталлятор раскатывает новую версию, CCM восстанавливает конфигурацию.

### Миграция LDAP/FreeIPA

@Александр Усков: была задача от Виталия Козловского — миграция из FreeIPA на LDAP Pro для BillManager. Инструкция от LDAP-команды существует, не проверена. Параллельно пришёл запрос обратно — из LDAP Pro в FreeIPA.

@Александр Лещев: если платформа будет на IPA, то существующие инсталляции с LDAP станут неподдерживаемой конфигурацией. Нужен механизм миграции для обновления. Пока прорабатывается первичное развёртывание, обновление — следующий этап.

### vGPU и BillManager

vGPU — passthrough PCI-устройство, не кластеризуется, не учитывается как ресурс в Brest. @Дмитрий Тайлаков: задача по кластеризации есть, но зависит от BillManager.

**Решение:** идти на целевую архитектуру (VLC/собственный портал), минуя BillManager. Признано, что с BillManager коммуникация не складывается, доработки через него уйдут в май 2027.

### Квота-менеджер / оркестратор

В рамках отщепления от BillManager нужно разрабатывать:
- Собственный квота-менеджер
- Оркестратор ресурсов (VLC — портал самообслуживания)
- Управление ресурсами через шедулинг Brest

@Александр Лещев: VLC — лицо облака, один разработчик не справится. Нужны дополнительные ресурсы.

@Дмитрий Тайлаков: май 2027 — маловероятный срок для полного цикла. Прототип — вторая половина осени.

- [x] Вопросы по доработке по запросам в сторону ПСБ ✅ 2026-05-14
	1. При использовании синхронизации c LDAP клиентов, пользователь не может сменить пароль в кабинете Bill Manager. Если он сменит, то не сможет войти ни под старым ни под новым паролей. Диалог об истечении пароля не выходит, пользователь может продолжать использовать просроченный пароль.
		- Такой путь является некорректным. Простое решение — убрать эти функции из UI Билла. Правильное решение — выводить эти функции в IAM.
	2. При синхронизации с LDAP используется УЗ с полномочиями администратора домена.
		- Сделали, видимо, чтобы просто работало. Простое и правильное решение — скорректировать инсталлятор, чтобы он использовал служебную УЗ для доступа к LDAP.
	3. Ограничения в знаках имен подразделений LDAP не позволяют реализовать сценарии именования клиентов использующих доп. символы в названии, при этом локально такое название создать можно.
		- Это историческое наследие — хранить организации в каталоге ALD. Правильно было бы выносить из каталога эту функцию. Простое решение — смириться с ограничениями ALD в части именования орг. юнитов.
	4. Иерархия считывания пользователей клиента не позволяет организовать иерархию хранения сотрудников клиента в LDAP (все пользователи должны лежать в одном OU, как и все клиенты)
		- Это служебный каталог. Он не предназначен для выстраивания собственной иерархии и орг. структуры
	5. Привязка групп при таком размещения приводит к тому что в одном коннекторе требуется описывать сотни групп (мапинг доменных к локальным ролям).
		- Желание иметь условно 100 кастомных ролей в Билле неизбежно приводит к необходимости их маппинга со 100 группами.
	6. При использовании консоли VM требуется прописывать доступ к фронту Brest причем по IP (переадресация в конфигах сделана по IP) — что снижает безопасность инсталляции.
		- Тут не подскажу, не моя тема.
	7. Не редактируется карточка ролей пользователя:
		- Аналогично пункту 1.
	8. Нельзя поменять УЗ и пароль служебного пользователя и группу под которым зарегистрирован/создается виртуальный датацентр.
		- Это служебные сущности и их изменения не предусмотрены

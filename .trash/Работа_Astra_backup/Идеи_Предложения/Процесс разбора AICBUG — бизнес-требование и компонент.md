# Процесс разбора AICBUG: бизнес-требование + компонент + гейт ТПМ

## Проблема

На встречах PBR (разбор AICBUG) решение «берём» принимается **до** того, как профильный ТПМ подтвердил реализуемость. В результате на встрече договорились «нужно брать», а в заведённом FR ТПМ отвечает «решения нет».

**Показательный кейс:**
- Исходный запрос: [AICBUG-123](https://jira.astralinux.ru/browse/AICBUG-123) «Нет возможности работать с группами клиентов» (RBAC-модель, автор Виктория Агафонова, 26.03.2025).
- Заведённый FR: [AIC-2129](https://jira.astralinux.ru/browse/AIC-2129) «Мапинг доменных к локальным ролям».
- Комментарий ТПМ в AIC-2129 (18.06.2026): *«создание доп. иерархий не предусмотрено… переход в ACP с ALDPro на FreeIPA»* — фактически «решения пока нет».

**Что не так:**
1. В AICBUG-123 нет бизнес-требования — только «реализовано ли такое же для групп пользователей? надо протестировать».
2. Не проставлен компонент → тикет не попал к профильному ТПМ до принятия решения.
3. Между AICBUG-123 и AIC-2129 **нет линка** — история не прослеживается.

## Предложение

### A. Обязательные поля в AICBUG (для типа «Предложение»)

1. **Бизнес-требование / проблема** — какую задачу клиента решаем и почему (не «реализовано ли Х», а «клиент не может …, из-за этого …»).
2. **Заказчик / организация** — метка или поле (нужно для приоритизации: один клиент или вся платформа).
3. **Компонент** — IAM / VIR / SCP / BIL / SDN и т.д. Ключевое: по компоненту тикет виден профильному ТПМ.
4. **Ожидаемый результат** — критерий готовности.

### B. Гейт «подтверждение реализуемости ТПМ» ДО статуса «берём»

На PBR решение фиксируется не как «берём», а как `К проработке [COMPONENT]`:
- Профильный ТПМ по компоненту (IAM → Виталий Козловский, VIR → Дмитрий Попенов, SCP → Михаил Перевалов, TMS → Максим Югай) даёт вердикт: **можно сходу / нужен R&D / нельзя (с обоснованием)**.
- Только после вердикта «можно» заводится FR (AIC-…) и линкуется с AICBUG.
- Так решение «берём» и техническая реализуемость не расходятся.

### C. Обязательный линк AICBUG ↔ FR (AIC)

- FR не заводится без линка на исходный AICBUG (и наоборот).
- AICBUG нельзя закрыть без линка на FR/решение.
- История запроса прослеживается, ответ ТПМ виден в контексте исходной задачи.

## Итог одной фразой

В AICBUG обязательны **бизнес-требование + заказчик + компонент**; на PBR прежде чем сказать «берём» — профильный ТПМ по компоненту подтверждает реализуемость; FR всегда слинкован с AICBUG.

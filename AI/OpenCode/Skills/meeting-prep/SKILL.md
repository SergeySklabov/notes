# meeting-prep - универсальная подготовка к встрече

Одна заметка на всю серию встреч одного типа (синки команды, синки с BillManager, архитектура и т.д.). Содержит актуальный контекст, незакрытые задачи, Jira-статусы и историю встреч.

## Имя Фамилия
**Цели спринта:** <цели одной строкой>

```tasks

tags include #<тег-серии>

### Jira 2.2.0 - <Компонент>
**[AIC-XXXX](url)** ❗ - <название>

**Правила:**
- Задачи не дублируются в prep — собираются динамически через `tasks` блоки из протоколов
- Jira-эпики сгруппированы по ответственному (под его секцией)
- Для каждого участника: цели спринта -> `tasks` блок -> Jira по компонентам

## Pipeline

### Шаг 1: Определить встречу и её тип

По названию и участникам определить серию встреч и найти соответствующую prep-заметку.

### Шаг 2: Обновить контекст предыдущей встречи

Из последнего протокола извлечь:
- **Решения** - статус выполнения (✅ / ⏳ / 🔴)
- **Незакрытые чекбоксы** (`- [ ]`) - скопировать в секцию участника сгруппировав по дате
- **Выполненные чекбоксы** (`- [x]`) - оставить в протоколе, в prep не копировать
- **Встречи** - обновить статус проведённых/непроведённых

### Шаг 3: Обновить задачи по участникам

Для каждого участника:
1. Обновить **Цели спринта** (для командных синков)
2. Добавить Jira-эпики 2.2.0 по компонентам участника

### Шаг 3.5: Задачи — динамические `tasks` блоки

**Протоколы — источник истины для чекбоксов.** Prep-заметки не дублируют чекбоксы вручную, а собирают их динамически через Obsidian Tasks plugin.

В prep-заметке:
```markdown
# Все открытые задачи

`+"```"+`tasks
not done
tags include #<тег-серии>
sort by due
group by due
`+"```"+`
```

**Теги по сериям:**
| Серия | Тег |
| --- | --- |
| Синки команды | `#teamsync` |
| Архитектура | `#architecture` |
| Синки с BillManager | `#billmanager` |
| UseCase ЛК | `#lk` |
| Синки с RnD | `#rnd` |

**Правила:**
- Чекбоксы живут только в протоколах встреч (в разделах `## Задачи`)
- Prep-заметка собирает их через `tasks not done tags include #тег`
- При создании нового протокола — отметить выполненные задачи предыдущего протокола как `[x]`
- Удалять `[ ]` чекбоксы из протоколов **не нужно** — `tasks` блок сам фильтрует по `not done`

### Шаг 4: Обновить секцию встреч

- Проведённые - тезисно что решили + ссылка на протокол
- Не проведённые - таблица с причиной и след. шагом

### Шаг 5: Связать с предыдущими встречами

Внизу - ссылки на все предыдущие протоколы этой серии.

# Meeting Minutes (Минутки / Момы)

Составление минуток (мом) из транскрибации разговора. Стиль - как у Сергея Склабовского в Confluence «Протоколы встреч» (Департамент облачной платформы).

**Важно:** этот скилл отвечает только за блок `## Протокол встречи` (повестка, решения, задачи). Полный протокол с анализом (AAR, портреты, стейкхолдеры, зависимости) - в `meeting-protocol`.

## Использование

Загрузи скилл, когда нужно:
- Составить минутки по транскрибации встречи
- Разобрать встречу типа «Разгребаем предложения / Air Bug PBR / приоритизация»
- Оформить решения по тикетам Jira в едином стиле

## Тип встречи-примера

**PBR в AIR BUG** - периодический разбор входящих запросов/багов (AICBUG-*, AIC-*).
Ведущий проходит по тикетам в доске приоритизации и по каждому фиксирует **решение** и **ответственного**.

## Принцип: транскрипт -> минутки

Транскрибация - сырой, «разговорный» текст с оговорками. Минутки - сухая выжимка **решений**, НЕ пересказ диалога.

Правила извлечения:
1. **Одна строка = один тикет = одно решение.** Игнорируй процедурный шум (проверки связи, «меня слышно?», шутки).
2. Каждый тикет -> ссылка на Jira + краткое решение + `@Ответственный`.
3. Опирайся на **финальные** формулировки ведущего («короче, берём…», «окей, закрываем…», «давайте так напишем»), а не на промежуточные рассуждения.
4. Сохраняй фактические номера тикетов из транскрипта/доски. Если номер назван неточно («сто двадцать четвёртый») - сопоставь с реальным ключом AICBUG-124.
5. Имена участников -> `@Имя Фамилия` (см. `assets/participants.md`).

## Словарь решений (как формулирует ведущий)

| Ситуация в транскрипте | Формулировка в минутках |
|---|---|
| «берём в работу / проработку», «занесём в 2.2» | `берём в проработку в <релиз> при наличии капасити команды` |
| «закрываем, непонятно зачем / старьё» | `закрываем запрос т.к. не ясна цель и нет возможности выяснить` |
| «полная переработка сценария» | `закрываем запрос т.к. полная переработка сценария` |
| «нужна фактура / контекст / ролевая модель» | `нужно уточнение контекста/ролевой модели. Подготовить фактуру - @X @Y отправить в тикет и тегнуть @Z` |
| «уточнить у ИБ / у бизнеса» | `@X @Y уточняют у ИБ ...; если ок - заводят FR, слинковать и закрыть` |
| «это к бил-менеджеру / новый ЛК» | `в работе в рамках <TMS/нового ЛК> - нужны FR, слинкованные с запросом` |
| «проверить связь с багом» | `проверить связь задачи с Багом AICBUG-XXX. Если одно и то же - закрываем в рамках бага` |
| «ждём патч» | `ждём патча от <X> ориентировочно <срок> - поставить в <релиз>` |
| «проверить сценарий» | `@X запусти проверку сценария в <системе>. Далее завести FR (новый ЛК) и слинковать` |

## Структура минуток

### Решения по тикетам (PBR)

Каждый тикет - строка с Jira-ссылкой, решением и ответственным:

```markdown
- <Jira URL> - <решение> - @Ответственный
- <Jira URL> - <решение>
- Группа FR'ов (новый ЛК) - @Ответственный
    - <Jira URL>
    - <Jira URL>
- Задачи по инсталлятору - @Даниил Копцев
    - <Jira URL>
    ...
```

### Решения (статус-митинги)

Два подраздела: организационные решения (поручения всем) и релизные решения:

```markdown
### Решения

#### Организационные решения
- **Всем** <срок> <что сделать>
- <решение>

#### Релиз <версия>
- <решение по релизу>
```

### Задачи

Два блока: таблица (для отправки) + чекбоксы (для Obsidian Tasks):

```markdown
### Задачи

| Кому | Что | Срок |
| --- | --- | :---: |
| Имя Фамилия | <действие> | ДД.ММ |

- [ ] <действие> #Фамилия_Имя 📅 YYYY-MM-DD #встреча
- [ ] <действие> #Фамилия_Имя #Фамилия_Имя2 📅 YYYY-MM-DD #встреча
```

- Таблица - для отправки протокола вовне (имена без тегов и ссылок)
- Чекбоксы ниже - для Obsidian Tasks (`#Фамилия_Имя` подтягивает задачу в заметку коллеги)
- `#встреча` - маркер, что задача родилась на встрече
- Дата в чекбоксе - ISO (`📅 2026-07-13`)

Шаблон: `assets/minutes-template.md`
Эталон (реальные минутки): `assets/example-minutes.md`

## Привязка к событию календаря

Каждая встреча = событие в календаре SOGo. Обязательно найди его и привяжи к минуткам.

1. Загрузи скилл `calendar-sync`.
2. Найди событие на дату встречи:
   `bash Scripts/calendar-detail.sh YYYY-MM-DD` (в `AI/OpenCode/Scripts`).
3. Сопоставь по названию/времени (напр. «PBR в AIR BUG», 17:00).
4. Достань UID и LOCATION (Dion) из ICS:
   `GET .../Calendar/personal.ics`, найди VEVENT с нужным SUMMARY.
   Recurring-события имеют один UID на все повторения - конкретную встречу идентифицирует UID + дата (`DTSTART`/`RECURRENCE-ID`).
5. Запиши метаданные в frontmatter заметки:

```yaml
---
tags:
  - meeting
  - meeting/air-bug
Дата: 2026-06-18
Время: "17:00-18:00"
Событие: PBR в AIR BUG - Разгребаем запросы
Событие_UID: 379E59-6A074100-5-521A6F80
Dion: https://dion.vc/event/ssklabovskii-team
Организатор: ssklabovskii@astralinux.ru
---
```

И строкой в теле: `**Событие календаря:** [<название>](<Dion>) - ДД.ММ.ГГГГ, ЧЧ:ММ-ЧЧ:ММ`.

## Куда сохранять

Сохранять в Obsidian сразу, без показа черновика: `Работа/Astra/Встречи/Протоколы встреч/<папка-типа>/YYYY-MM-DD <Название>.md`.
Vault для MCP-инструментов: `sergey-s-vault`.

## После сохранения — обновить prep-заметку

**ОБЯЗАТЕЛЬНО** после создания минуток обновить сводную prep-заметку серии (см. `meeting-prep`):

1. Обновить `**Прошедшая встреча:**` — ссылка на текущий протокол
2. Обновить `**Следующая встреча:**` — если известна дата
3. Добавить протокол в `# Предыдущие встречи`
4. Обновить `# Контекст` — перенести решения со статусами, общие задачи

Маппинг серий и prep-заметок:

| Серия | Prep-заметка |
| --- | --- |
| PBR / Air Bug | `Протоколы встреч/PBR/PBR Air Bug.md` |
| Синки с BillManager | `Протоколы встреч/Синк с BillManager/Синки с BillManager.md` |
| UseCase ЛК | `Протоколы встреч/Личные Кабинеты/UseCase для ЛК.md` |
| Синки с RnD | `Протоколы встреч/Синки с RnD/Синки с RnD.md` |

## Правила оформления

- Тире в тексте: только дефис `-`, не длинное тире `-`
- В frontmatter `Время`: кавычки, дефис между часами: `"11:30-13:00"`
- Имена участников: `@Имя Фамилия`

Сохранять в Obsidian сразу, без показа черновика.

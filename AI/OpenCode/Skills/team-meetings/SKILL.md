# team-meetings - шаблоны встреч команды

Для каждой recurring-встречи - свой формат brief: контекст предыдущей встречи, незакрытые задачи, структура под тип.

---

## Pipeline

### Шаг 1: Определить тип встречи

| Тип | Паттерн названия | Периодичность |
|-----|------------------|--------------|
| **Team planning** | Планирование команды | Начало цикла (2 нед) |
| **Team sync** | Статус команды / синк | Середина/итог цикла (2 нед) |
| **1-2-1** | 1-2-1 *Имя* | Еженедельно / по графику |
| **PBR** | PBR / AICBUG / Разгребаем запросы | Раз в 1-2 недели |
| **Арх.ком** | Архитектура / ADR / Арх.ком | По необходимости |

### Шаг 2: Найти предыдущий протокол того же типа

Из последнего протокола извлечь общее для всех типов:

- **Решения** - выполнены или нет
- **Задачи** - какие просрочены, какие на сегодня
- **Блокеры/риски** - активные
- **Темы к отдельным обсуждениям** - отложенные

Для 1-2-1 дополнительно: **личные цели** (развитие, карьера, обучение, pet-проекты) и **обратная связь**.

Для PBR дополнительно: **список тикетов** к разбору (статус, кто добавил).

Для арх.кома дополнительно: **ADR-статус**, **связанные блокеры** в задачах спринта.

### Шаг 3: Сформировать brief под тип встречи

#### Team planning (название: «Планирование команды»)

Для каждого участника:
- **Итоги прошедшего спринта** - какие цели выполнены, какие нет, блокеры, side-активности, длинные фичи
- **Планирование** - цели на следующий спринт, потенциальные блокеры
- **Задачи с прошлой встречи** - статус

Далее - **общие задачи**.

```markdown
**Формат:**
для каждого участника:
- Итоги прошедшего спринта - какие цели выполнены, какие нет, блокеры, side-активности, длинные фичи
- Планирование: цели на следующий спринт - что планируется, потенциальные блокеры
- Задачи с прошлой встречи (ДД.ММ) - статус
```

#### Team sync (название: «Статус команды»)

Для каждого участника:
- **Промежуточные итоги текущего спринта** - какие цели выполнены, какие нет, блокеры, side-активности, длинные фичи
- **Задачи с прошлой встречи** - статус

Пункт «Планирование» отсутствует.

После участников - разделы:
- **Side-активности** (длинные фичи, полезное вне целей; если тема требует обсуждения - отдельная встреча)
- **Не влезло в спринт, но важно** (задачи, эскалации)
- **Незакрытые задачи с предыдущих встреч** (общие / индивидуальные, если не дублируют цели)

```markdown
**Формат:**
для каждого участника:
- Промежуточные итоги текущего спринта - какие цели выполнены, какие нет, блокеры, side-активности, длинные фичи
- Задачи с прошлой встречи (ДД.ММ) - статус
```

#### 1-2-1

```markdown
## 1-2-1: YYYY-MM-DD с @Имя

### С предыдущей встречи
- ✅ Выполнено: <список>
- ⏳ В работе: <список>
- ❌ Не выполнено: <список>

### Текущий статус
- **Личные цели / развитие:** <прогресс>
- **Что беспокоит / обратная связь:** <темы>
- **Блокеры в работе:** <список>

### На эту встречу
1. <тема 1>
2. <тема 2>
3. План на следующий период / цели

### Задачи после встречи
- [ ] <действие> #Фамилия_Имя 📅 YYYY-MM-DD #1-2-1
```

#### PBR (Product Backlog Refinement)

```markdown
## PBR: YYYY-MM-DD

### На разбор
| Тикет | Тема | Статус | Решение |
|-------|------|--------|---------|
| <ссылка> | <кратко> | новый / на уточнении / ... | берём / закрываем / ждём |

### Задачи
- [ ] <действие> #Фамилия_Имя 📅 YYYY-MM-DD #pbr
```

#### Архитектурный комитет

```markdown
## Арх.ком: YYYY-MM-DD

### Контекст
- **Связанные блокеры в спринте:** <список задач, зависящих от решений>
- **Прошлые ADR:** <статус>

### Адженда
1. <тема> - решение: <вариант A / B / C>
2. <тема> - решение: <вариант A / B / C>

### Решения и ADR
- **Решение:** <принятое решение>
- **Владелец:** @Имя
- **Срок:** ДД.ММ

### Задачи
- [ ] <действие> #Фамилия_Имя 📅 YYYY-MM-DD #arch-comm
```

### Шаг 4: Показать пользователю

Вывести brief, дождаться подтверждения или корректировок.

После встречи - записать протокол через `meeting-protocol` или `meeting-minutes`.

---

## Связанные скиллы

- `meeting-prep` - подготовка контекста (предыдущие протоколы, Jira)
- `meeting-protocol` - запись протокола по итогам встречи
- `meeting-minutes` - формат решений и задач
- `calendar-sync` - поиск события

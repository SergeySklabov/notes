# Obsidian Kanban Agent Ops

Цель: быстро и стабильно управлять Kanban-доской в Obsidian так, чтобы агент поддерживал поток задач без хаоса.

Шаблон карточки хранится в assets:
`assets/kanban-task-card-template.md`.

## Базовый протокол

1. Найди целевую доску.
2. Проверь колонки и текущий WIP.
3. Отсортируй карточки по правилам переходов.
4. Для больших задач используй linked-note карточки.
5. Не двигай карточку в `done` без DoD.

## Рекомендуемая структура колонок

1. `backlog`
2. `todo`
3. `in progress`
4. `done`

## Правила потока

- Держи `in progress` в лимите `1-3`.
- `backlog` только для несформулированных/отложенных задач.
- `todo` только для задач, готовых к старту.
- `done` только после проверки DoD.

## Правило декомпозиции

- В одной задаче держи минимально необходимое число подзадач.
- Подзадачи формулируй коротко и исполнимо.
- Целевой размер подзадачи: примерно `~30 минут` работы.
- Не дроби подзадачи на слишком мелкие шаги (< 30 минут), если это не требуется для контроля риска.

## Нейминг задач

- Названия задач пиши на русском.
- Название должно начинаться с глагола: `Сделать ...`, `Определить ...`, `Разработать ...`.
- Не добавляй название проекта в заголовок задачи.

## Исполнители (linked-note metadata)

- Исполнителя фиксируй в frontmatter linked-note полем `assignee`.
- Для отображения исполнителя на карточке используй настройку Kanban `Linked page metadata` и добавь ключ `assignee`.
- В теле карточки не дублируй исполнителя, если он уже есть в frontmatter.

## Шаблон linked-note задачи

Каждая execution-задача должна содержать:

- `Goal`
- `Definition of Done`
- `Plan`
- `Subtasks`

Формат `- [ ]` (tasks/checkboxes) используй только внутри раздела `Subtasks`.

Для `Goal`, `Definition of Done` и `Plan` используй обычный текст/пункты без чекбоксов.

Если пользователь просит создать шаблон или новую linked-note задачу, используй файл
`assets/kanban-task-card-template.md` как базу.

## Переходы карточек

- `backlog -> todo`: задача прояснена и готова к работе.
- `todo -> in progress`: начата работа и определен следующий шаг.
- `in progress -> done`: DoD выполнен.
- `in progress -> todo`: задача поставлена на паузу.
- `todo -> backlog`: задача отложена или переприоритизирована.

## Персонализация по проектным тегам

При создании/редактировании карточек проставляй один проектный тег:

- `#claw` -> проект Claw
- `#PA` -> проект PA
- `#MED` -> проект MED
- `#yoger` -> проект yoger

Если тег не указан пользователем явно, выбирай по контексту задачи и зафиксируй это в ответе.

## Инструменты

- Для поиска доски: `Cmd/Ctrl + O` или `obsidian search query="kanban" format=json`.
- Для открытия: `obsidian open path="<board or note>.md"`.
- Для проверки архива: `Kanban: Toggle between Kanban and markdown mode`.

## Антипаттерны

- Не держи слишком много задач в `in progress`.
- Не оставляй тяжелые задачи без linked note.
- Не ставь `done` без DoD.
- Не смешивай несколько проектных тегов в одной карточке.
- Не используй чекбоксы вне раздела `Subtasks`.

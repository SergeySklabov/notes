# Tag Lifecycle — работа с тегами в SCP

> **Обновлено:** 2026-07-04 — добавлен `#Знания` (перенос фактов на страницы компонентов)

> **Цель:** Единый процесс маркировки контента тегами и последующей обработки.
> **Механизм:** Разметка в заметках → периодический сбор → обработка → закрытие.

---

## Список тегов

| Тег         | Назначение                          | Кто ставит | Что делает обработчик                                                                                                 |
| ----------- | ----------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------- |
| `#TODO`     | Нужно сделать / проработать         | Любой      | Берёт в работу или переводит в задачу                                                                                 |
| `#check`    | Нужно проверить / верифицировать    | PO         | Проверяет, сверяет с фактами                                                                                          |
| `#PO-check` | Требуется решение/внимание PO       | Любой      | Анализирует, находит решение, меняет на `#checked`                                                                    |
| `#checked`  | Проверено, решение принято          | Обработчик | Финализирующий тег — означает, что вопрос закрыт                                                                      |
| `#who`      | Не назначен ответственный           | Любой      | Определяет ответственного или формулирует вопрос                                                                      |
| `#ba`       | Нужен бизнес-анализ / BA            | Любой      | Передаёт BA-агенту или владельцу US                                                                                   |
| `#asked`    | Вопрос задан, нужен контроль ответа | Любой      | Отслеживает статус ответа, закрывает при получении                                                                    |
| `#Знания`   | Факт/знание из общения с коллегой   | Любой      | Собирает все `#Знания` у коллег → переносит на страницу компонента (ответственного) → удаляет факт из заметки коллеги |

## Жизненный цикл тега

```
Создание                  Обработка                  Закрытие
─────────                ──────────                 ────────
                          ┌─────────────┐
#TODO ──────────────────→│ Беру в работу │──→ Выполнено → удалён
                          └─────────────┘

                          ┌─────────────┐
#check ─────────────────→│ Верифицирую  │──→ Подтверждено → #checked
                          └─────────────┘

                          ┌─────────────┐
#PO-check ──────────────→│ Анализирую   │──→ Решение найдено → #checked
                          │ + нахожу     │
                          │   решение    │
                          └─────────────┘

                          ┌─────────────┐
#who ───────────────────→│ Назначаю     │──→ Ответственный определён → #checked
                           │ или          │
                           │ формулирую   │
                           └─────────────┘

                           ┌──────────────────────┐
#Знания ────────────────→│ Сбор по заметкам      │──→ Факт перенесён на
                           │ коллег → определение  │    страницу компонента
                           │ компонента →          │    → удалён из заметки
                           │ перенос факта         │    коллеги
                           └──────────────────────┘
```

**Правила:**
1. Теги не удаляются из файлов — заменяются на `#checked` с комментарием
2. `#checked` содержит дату и суть решения (например, `#checked 19.06 — BillManager, решено с Сергеем`)
3. Если тег не может быть обработан — ставится `❓ #open` с причиной
4. Обработка тегов происходит циклически: по запросу PO или автоматически при анализе заметок

## Процесс обработки

### Шаг 1. Сбор
При получении запроса на обработку тегов программа:
- Сканирует все `.md`-файлы в `SCP/` и `Команда/Команда Платформы AC/`
- Ищет необработанные теги: `#TODO`, `#check`, `#PO-check`, `#who`, `#ba`, `#Знания`
- Составляет полный реестр

### Шаг 2. Классификация
Каждый тег относится к одному из типов:

| Тип | Пример | Действие |
|-----|--------|----------|
| **Информационный** | `#check пройтись по всему` | Прочитать контекст, подтвердить |
| **Вопрос/решение** | `#PO-check квоты не MVP` | Найти ответ в документах или запросить у PO |
| **Действие** | `#TODO расписать механизм` | Выполнить или отложить с причиной |
| **Назначение** | `#who отвечает за тенанты?` | Определить ответственного |

### Шаг 3. Обработка
Для каждого тега:
1. Прочитать окружающий контекст (заметку целиком или блок)
2. Определить, решён ли вопрос текущими документами/решениями
3. Если решён — записать решение, заменить тег на `#checked`
4. Если не решён — сформулировать вопрос PO, оставить тег

**Для `#Знания` (особый случай):**
1. Определить страницу компонента по ответственному коллеге (например, Дмитрий Попенов → `Брест (VIT)/Брест (VIT).md`)
2. Перенести факт в секцию `# Знания` на странице компонента
3. В заметке коллеги: заменить блок `**Стало известно:**` на ссылку на страницу компонента, удалить тег `#Знания` и детальное описание факта
4. В `# Знания` на странице коллеги: добавить ссылку на страницу компонента (если ещё нет)

### Шаг 4. Фиксация
- Заменить исходный тег на `#checked ДД.ММ — суть решения`
- В лог обработки добавить запись
